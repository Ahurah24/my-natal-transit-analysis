# ربات ترید ارزینجا — نسخه ویندوز

رابط محلی **Python + FastAPI + React**. سرویس‌ها روی 127.0.0.1 اجرا می‌شوند.

## نصب و اجرا
- Windows 10/11 x64، Python 3.11+ و Node.js LTS لازم است.
- در پوشه پروژه PowerShell را باز کن و در صورت نیاز فقط برای همین نشست اجرا کن:
  `Set-ExecutionPolicy -Scope Process Bypass`
- نصب: `./install_windows.ps1`
- اجرای کامل (Backend + Dashboard): `start_windows.bat`
- اجرای جداگانه Backend: `start_backend.bat` (برای زمانی که داشبورد از قبل باز است یا Backend متوقف شده)
- داشبورد: http://127.0.0.1:5173
- API: http://127.0.0.1:8000/docs
- پنجره Backend را باز نگه دار؛ برای توقف سرویس از `Ctrl+C` در همان پنجره استفاده کن.

## تنظیم API و محدودیت سرویس
1. کلیدهایی را که قبلاً در چت افشا شده‌اند در پنل ارزینجا باطل کن.
2. کلید جدید را فقط در فایل محلی `.env` قرار بده؛ این فایل نباید وارد Git شود.
3. میزبان پیش‌فرض API روی `https://api-v2.arzinja.ir/api` تنظیم شده است.
4. این پروژه فقط برای بازارهای P2P و سرویس Advanced Trade طراحی می‌شود؛ مسیر OTC در آن استفاده نمی‌شود.
5. کارمزد Maker و Taker در شبیه‌سازی فعلی Advanced Trade برابر صفر تنظیم شده است، مطابق صفحه راهنمای Advanced Trade و اطلاعات حسابی که کاربر ارائه کرده است. این تنظیم به معنی صفر بودن اسپرد یا لغزش قیمت نیست.
6. مقدار `isZeroFee` در پاسخ بازار، معیار تشخیص کارمزد حساب کاربر نیست و در انتخاب بازار استفاده نمی‌شود.

## امکانات فعلی شاخه توسعه
- کلاینت API با HMAC برای مسیرهای خصوصی (فرمت امضا هنوز با درخواست خصوصی واقعی اعتبارسنجی نشده است).
- دریافت فهرست بازار P2P از مسیر آزمایش‌شده `/v1/market/all-market` و بازکردن ساختار تو‌در‌توی پاسخ.
- فیلتر بازار بر اساس فعال بودن هم‌زمان خرید و فروش.
- دریافت تاریخچه OHLCV از مسیر آزمایش‌شده `/v1/trade/trading-view/history` با تایم‌فریم‌های 5، 15 و 60 دقیقه.
- اعتبارسنجی اولیه ساختار کندل‌ها، مقادیر OHLC و ترتیب زمانی.
- اسکن دفتر سفارش، محاسبه اسپرد و عمق پنج سطح اول؛ مسیر و ساختار پاسخ با مستندات رسمی ارزینجا تطبیق داده شده، اما پاسخ زنده میزبان API در این محیط دریافت نشده است.
- مدیریت ریسک و دفترکل Paper Trading محلی با SQLite.
- ماژول‌های ML و یادگیری افزایشی؛ هنوز به چرخه کامل تولید سیگنال و بسته‌شدن معامله Paper متصل نشده‌اند.

## API تاریخچه کندل
نمونه:
`GET /api/exchange/history?symbol=BTCIRT&resolution=15&days=7&currency_code=IRT`

مقادیر مجاز resolution: 5، 15 و 60 دقیقه. آخرین کندل برگشتی ممکن است هنوز باز باشد؛ موتور استراتژی باید فقط از کندل‌های بسته‌شده استفاده کند. صحت ساختاری داده به‌تنهایی جایگزین تطبیق قیمت با دفتر سفارش و آزمون روی چند بازار نیست.

## وضعیت اعتبارسنجی API
- مسیر Orderbook مستندشده: `GET /v1/services/trade/p2p/orderbook` با `pair` و `limit`؛ پاسخ نمونه رسمی دارای `result.bids` و `result.asks` به شکل `[price, quantity]` است.
- رشته HMAC مطابق نمونه رسمی ساخته می‌شود: برای GET، `timestamp + apiKey + recvWindow + queryString` و برای POST، `timestamp + apiKey + recvWindow + body`.
- آزمون‌های واحد برای payload امضا و شکل پاسخ دفتر سفارش اضافه شده‌اند؛ این آزمون‌ها جایگزین یک درخواست زنده نیستند.

## مواردی که پیش از استفاده واقعی باید تکمیل شوند
- تأیید زنده مسیر و schema دفتر سفارش، موجودی و درخواست‌های خصوصی.
- اعتبارسنجی HMAC: رشته امضا با نمونه رسمی Postman تطبیق داده شده و آزمون واحد برای ترتیب اجزای payload اضافه شده است؛ پذیرش امضا با درخواست خصوصی واقعی هنوز تأیید نشده است.
- اتصال داده کندل به feature engineering، استراتژی و بک‌تست walk-forward.
- اجرای Paper Trading پیوسته، ثبت هزینه اسپرد و لغزش، و اتصال نتیجه معامله به یادگیری مدل.
- مدیریت سفارش، partial fill، لغو، retry، idempotency و بازیابی پس از قطع اتصال.
- آزمون کامل چند بازار و چند بازه زمانی.
